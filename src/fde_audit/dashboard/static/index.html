What this app does

FDE Audit watches your own work — it screenshots your active window every few seconds into a local SQLite database (nothing leaves your machine, no API key, no cloud). Claude Code then looks at those screenshots, labels what you were doing, and prices improvement opportunities — things worth automating, consolidating, or eliminating, each with an estimated reclaimable minutes-per-week. This dashboard is the window over that database.

Starting the app — two commands, two terminals

The recorder and the dashboard are separate processes. Open two terminals in the project folder:

Terminal 1 — record your work (leave it running; Ctrl+C stops it)
.\.venv\Scripts\fde_audit.exe capture start
Terminal 2 — serve this dashboard
.\.venv\Scripts\fde_audit.exe dashboard
then open http://127.0.0.1:8787 in a browser.

The dashboard on its own captures nothing — it only reads the database and triggers analysis steps. While the recorder runs, the Awaiting analysis tile on Overview counts up as new frames land (hit Refresh to re-query).

Getting an improvement report — the 4-step loop

Everything happens in the Run analysis panel (the Analysis button in the top bar opens it). Steps 1 and 3 are buttons here; steps 2 and 4 are done in Claude Code — that's where the AI lives.

  1. Prepare vision analysis (button) — bundles the frames not yet analyzed into a packet. Instant, no model.
  2. Label in Claude Code — open Claude Code and say: “Label and commit the prepared analysis packet.” Claude reads the screenshots and writes labeled sessions and priced opportunities into the database.
  3. Compile report + brief packet (button) — ranks the opportunities into a saved data report (see Reports) and bundles a brief packet for the selected period. Instant, no model.
  4. Write brief in Claude Code — say: “Write the executive brief from the prepared brief packet.” The narrative brief (themes, tools worth building, licenses to cut) lands under Reports.

Repeat the loop whenever “Awaiting analysis” has piled up; re-run steps 3–4 any time you want a fresh brief for the selected period.

The pages

  • Overview — capture and analysis at a glance: work/idle time, frames awaiting analysis, reclaimable minutes per week.
  • Activity — where the captured time went: time by app and per-day work minutes.
  • Opportunities — the ranked improvement ledger with weekly cost, status, and evidence counts.
  • Runs — each vision-labeling pass; click a run to see the sessions it labeled.
  • Reports — saved data reports and executive briefs; click one to read it.

Tips

  • The Department / Person / Period filters in the top bar scope every page. Picking a department views the whole team; picking a person clears the department.
  • ◐ toggles light/dark theme; your choice is remembered.
  • The Analysis button shows a badge when frames are waiting and a pulse while a job is running.
  • Sensitive apps (password managers, banking) are denylisted — only metadata is recorded for them, never images.

Full walkthrough — how do I get an improvement report?
  1. Capture your screen — in a terminal, from the project folder, run .\.venv\Scripts\fde_audit.exe capture start and leave it running (Ctrl+C stops it). Screenshots land in the database in real time; the Awaiting analysis tile on Overview counts the frames not yet analyzed.
  2. Step 1 — Prepare vision analysis — bundles the new frames into a packet (no AI model needed). The job log below prints the exact commit command for the next step.
  3. Step 2 — label it in Claude Code — this is where the AI does its improvement-finding. Say: “Label and commit the prepared analysis packet.” Claude looks at the screenshots with vision, works out what you were doing and where time is being lost, and writes the labeled sessions and priced improvement opportunities into the database. Everything after this step is arithmetic over what Claude wrote here.
  4. Step 3 — Compile report + brief packet — two instant, model-free processes. First it ranks the opportunities into a data report (weekly cost, evidence, consolidation candidates), saved under Reports. Then it bundles the ledger plus the selected period's activity into a brief packet for the next step.
  5. Step 4 — have Claude Code write the brief — the narrative report: themes, custom apps worth building, licenses to cut, next steps. Say: “Write the executive brief from the prepared brief packet.” Claude writes the Markdown and commits it, saving it under Reports (period exec-…).

Where the AI happens: steps 2 and 4 (in Claude Code, no API key). Steps 1 and 3 are instant bookkeeping. Repeat the loop whenever “Awaiting analysis” has piled up; re-run steps 3–4 whenever you want a fresh brief for the selected period.
